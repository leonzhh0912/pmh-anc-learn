# Development guide

## Architecture

```
content/  (JSON, edited by people or a future Git-based CMS)
   │  lessons/*.json ── validated by app/src/content/schema.ts (zod)
   │  video-scripts/*.json ── narration + on-screen text + captions, one file per video
   │  videos/*.json ── generated by video/scripts/publish.mjs
   ▼
video/ (Remotion)                         app/ (React PWA)
 narrate.mjs → audio + timing + VTT        imports content/ at build time
 LessonVideo.tsx → MP4                     plays app/public/media/*.mp4 with <track> captions
 publish.mjs → app/public/media/ ────────► static build (dist/) → any static host
```

Why a PWA: works in any phone browser from a QR code with no install, can be added to the home screen,
caches lessons for offline use, needs no app-store accounts, and one codebase serves phone, tablet and
desktop. No backend is needed while progress is anonymous and local.

Why JSON content in Git: every change is versioned and reviewable, and it can be validated automatically.
Later, a Git-backed CMS (Decap CMS or Sveltia CMS) can give ANC staff web forms over the same files
without a database. See "Staff content editing" below.

### App (`app/`)

- `src/content/schema.ts`: the lesson, quiz, step, video and section types. Change content shape here first.
- `src/content/load.ts`: build-time import of `content/`. Only APPROVED/PUBLISHED is authoritative (`isApproved`).
- `src/pages/`: Home (handbook tabs), Section, Lesson (step player), About.
- `src/components/`: `Quiz`, `Timeline`, `SortGame`, `VideoPlayer`, `DraftBanner`, `PageChip`.
- `src/lib/progress.ts`: anonymous local progress and text size, `localStorage` with in-memory fallback.
- `src/lib/pages.ts`: PDF page → printed page label.
- Styling: plain CSS with tokens in `src/index.css` (palette from the handbook's cover and tabs; Sarabun font,
  self-hosted, so it works offline). Base body size 19 px; users can scale to 130 %.
- PWA: `vite.config.ts`. App shell, fonts, data, captions and posters are precached; MP4s are cached
  on first play only.

### Video (`video/`)

1. **Script**: `content/video-scripts/<id>.json` has scenes (`title`, `stage`, `summary`) and segments
   (`speak` = what the voice says, numbers written as words; `caption` = what is shown, digits allowed;
   `reveal` = which item appears).
2. **Narrate**: `npm run narrate <id>` creates one WAV per segment, measures it, and writes
   `src/generated/<id>.timing.json` and `out/<id>.th.vtt`. Scenes are sized to the audio.
   - Voice: ElevenLabs `eleven_v3` (production) or `macos-say` (offline draft), set in the script's `voice`
     block. See docs/VOICE.md. The API key lives only in git-ignored `video/.env.local`.
   - **Recorded narration**: drop `public/audio/<id>/recorded/<sceneId>-<n>.wav` files, re-run narrate.
     No code changes needed.
3. **Render**: `npm run render <id>` gives `out/<id>.mp4` (captions as a separate track) and
   `out/<id>-captioned.mp4` (captions burned in, for sharing on LINE).
4. **Publish to app**: `npm run publish-to-app <id>` copies the MP4, VTT and poster to `app/public/media/`
   and writes `content/videos/<id>.json`.
5. All in one: `npm run video <id>`.

Remotion Studio for previewing and editing: `npm run dev` (port 3000).

To add a new scene type, add it to `video/src/lesson/types.ts` and `LessonVideo.tsx`. Icons are original
SVGs in `Icon.tsx`. Register each new video in `video/src/lesson/registry.ts`.

## Git workflow

- `main` is always deployable: validation and tests pass.
- Work on short-lived branches: `lesson/<ID>` for content, `feat/<topic>` for app or video features,
  `fix/<topic>` for fixes. Open a pull request into `main`, even when working alone, so changes and
  reviewer approvals have a visible record.
- Before pushing: `cd app && npm run validate:content && npm run test:e2e`.
- Commit messages say what changed and, for approvals, who approved (see CONTENT_REVIEW.md).
- Releases are tags on `main` (`v0.1.0`, …), see DEPLOYMENT.md.
- Never commit secrets, patient data, or the handbook PDF (`.gitignore` covers these).

## Setting up a new computer

1. Install Node.js 22 or 24 LTS, Git and ffmpeg (`brew install node git ffmpeg`).
2. `git clone` the repository.
3. `cd app && npm ci && npx playwright install chromium`
4. `cd ../video && npm ci`
5. Optional: download the official handbook PDF (URL in `content/handbook-source.json`) to
   `handbook/source/MCH-2568-official.pdf` and check its sha256.
6. `cd ../app && npm run dev`, then open the printed LAN URL on a phone on the same Wi-Fi.

Nothing in the project is tied to one person's Mac or AI account. Claude Code is optional.

## Adding a lesson

1. Pick the lesson in `content/curriculum.json` / CURRICULUM.md (ID, pages, objectives).
2. Copy `content/lessons/MCH68-OVR-001.json` to `content/lessons/<ID>.json`. Keep `status: "DRAFT"`.
3. Write steps (`text`, `timeline`, `sort`, `video`, `quiz`, `takeaways`). Every quiz question needs
   per-option `feedback`, an `explanation` and a `source`.
4. `cd app && npm run validate:content && npm run dev` and check it at phone width.
5. Add or extend a Playwright test in `app/tests/`.
6. Update the lesson's `status` in `content/curriculum.json` and log it in `docs/PROGRESS.md`.
7. Send for review (CONTENT_REVIEW.md).

## Staff content editing (planned, not built yet)

Recommended path once the content shape settles: add Decap CMS or Sveltia CMS at `app/public/admin/`,
configured over `content/lessons/*.json`, with GitHub login restricted to authorised PMH editors and an
"editorial workflow" that opens pull requests. Reviewers approve in GitHub, and the build validates.
No database or server needed. Keep `npm run validate:content` as the gate.

## Testing

- `npm run validate:content`: schema, references, file names, approval fields. `--production` also
  rejects any non-approved lesson/video or draft TTS.
- `npm run test:e2e`: Playwright against the production build, phone (Pixel 7) and desktop profiles:
  full lesson flow, retries, progress persistence, text size, captions served, no horizontal scroll at
  360 px, offline after first visit.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Playwright "Executable doesn't exist" | `npx playwright install chromium` |
| Thai text renders in a fallback font in video | check `video/public/fonts/` exists; `fonts.ts` loads Sarabun |
| `narrate` fails: `say` not found | the macOS draft voice needs macOS; use the ElevenLabs voice or recorded WAVs |
| `narrate` fails: `ELEVENLABS_API_KEY is not set` | create `video/.env.local` from `video/.env.example` |
| ElevenLabs HTTP 401 `missing_permissions` | the key must allow Text to Speech; read endpoints are intentionally blocked |
| Video scene timing looks wrong after editing a script | re-run `npm run narrate <id>` before rendering |
| Content change not visible | `validate:content` errors stop the build; check the console in dev |
| Old version after deploy on a phone | the service worker auto-updates on next load; reload once |
