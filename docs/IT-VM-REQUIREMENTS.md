# ข้อกำหนดเครื่องเสมือน (VM) สำหรับ ANC Learn — สำหรับฝ่ายไอที โรงพยาบาลพิมาย

ฉบับ 11 พ.ย. 2569 · ยังไม่ได้ติดตั้งอะไรบนระบบของโรงพยาบาล · ต้องได้รับอนุมัติจากฝ่ายไอทีและผู้บริหารก่อนติดตั้ง

**ใช้ทำอะไร:** เก็บบัญชีผู้เรียน/เจ้าหน้าที่ และความคืบหน้าการเรียนของแอป ANC Learn ไว้ในโรงพยาบาล (ไม่ใช้คลาวด์)
ไม่เก็บข้อมูลการรักษา ไม่เชื่อม HIS ไม่ส่ง SMS/อีเมล และไม่เปิดให้สมัครเอง (เจ้าหน้าที่สร้างบัญชี)

**ซอฟต์แวร์ที่จะติดตั้ง (ขออนุมัติ):** ทั้งหมดเป็นโอเพนซอร์ส ไม่มีค่าลิขสิทธิ์
- **Supabase แบบติดตั้งเอง** รุ่น `self-hosted/v0.8.4` = ชุดฐานข้อมูล PostgreSQL 17 พร้อมระบบล็อกอิน
  (ภายในมี 11 ส่วนประกอบ รันในคอนเทนเนอร์)
- **Docker** = โปรแกรมรันชุดซอฟต์แวร์แบบแยกส่วน (คอนเทนเนอร์) และเปิดเองอัตโนมัติเมื่อเครื่องบูต
- **Caddy** = เว็บเซิร์ฟเวอร์หน้าบ้าน ทำ HTTPS และขอใบรับรองจาก Let's Encrypt (ฟรี) อัตโนมัติ

## 1. CPU / RAM / ดิสก์
| | ขั้นต่ำ | แนะนำ |
|---|---|---|
| vCPU | 2 | 4 |
| RAM | 4 GB | 8 GB |
| ดิสก์ (SSD) | 40 GB | 80–100 GB |

ที่มา: ข้อกำหนดทางการของ Supabase self-hosting (ขั้นต่ำ 4 GB/2 คอร์/40 GB, แนะนำ 8 GB+/4 คอร์+/80 GB+)
และการซ้อมติดตั้งจริงด้วยตัวติดตั้งของโครงการบน Ubuntu 24.04 (11 พ.ย. 2569): ขณะทำงานปกติใช้ RAM ประมาณ 1.5 GB,
ซอฟต์แวร์ใช้ดิสก์ประมาณ 11 GB บวกระบบปฏิบัติการ, ข้อมูลเริ่มต้นน้อยกว่า 1 MB ส่วนที่เหลือเผื่อการเติบโต การอัปเดต และบันทึกระบบ
ผลการซ้อม: ติดตั้งครบ 11 ส่วนประกอบ, ตรวจจากภายนอกผ่าน 9/9 ข้อ, ทดสอบการใช้งานครบ 12/12 ข้อ, รีบูตแล้วทุกอย่างกลับมาเอง

## 2. ระบบปฏิบัติการ
- **Ubuntu Server 24.04 LTS** (64-bit; x86-64 หรือ ARM64) ติดตั้งแบบเปล่า ไม่ต้องมีโปรแกรมอื่น
- ผู้ใช้ 1 คนที่ใช้ `sudo` ได้, เปิด OpenSSH, ตั้งเวลา (NTP) ให้ถูกต้อง
- ตัวติดตั้งของโครงการรองรับเฉพาะ Ubuntu 24.04 (ตรวจและหยุดเองถ้าไม่ใช่)

## 3. เครือข่าย
**เปิดจากอินเทอร์เน็ต (ขาเข้า) — ไปที่ VM นี้เท่านั้น**
- TCP **443** (HTTPS) — แอปในมือถือผู้เรียนเชื่อมต่อทางนี้
- TCP **80** — ใช้ยืนยันโดเมนเพื่อขอ/ต่ออายุใบรับรอง HTTPS อัตโนมัติ (และส่งต่อไป 443)

**ต้องเป็นส่วนตัว (ห้ามเปิดจากภายนอก)**
- TCP **22** (SSH) — จากเครือข่ายภายใน/VPN ของไอทีเท่านั้น
- 8000, 5432, 6543 — ตัวติดตั้งผูกไว้กับตัวเครื่องเอง (127.0.0.1) อยู่แล้ว ไม่ต้องเปิดที่ไฟร์วอลล์
- หน้าแดชบอร์ดผู้ดูแลฐานข้อมูล ไม่เปิดสู่อินเทอร์เน็ต (เข้าผ่าน SSH tunnel เท่านั้น)

**ขาออก (VM ต้องออกอินเทอร์เน็ตได้) ผ่าน HTTPS 443 และ HTTP 80**
- ตอนติดตั้งและอัปเดต: แพ็กเกจ Ubuntu (`*.ubuntu.com`), Docker (`get.docker.com`, `download.docker.com`),
  อิมเมจซอฟต์แวร์ (`docker.io` / `registry-1.docker.io`, `*.docker.com`), GitHub (`github.com`,
  `raw.githubusercontent.com`), Caddy (`dl.cloudsmith.io`)
- ใช้งานต่อเนื่อง: Let's Encrypt (`acme-v02.api.letsencrypt.org`) ต่ออายุใบรับรองอัตโนมัติก่อนหมดอายุ และอัปเดตความปลอดภัยของ Ubuntu
- ไม่ต้องติดต่อผู้ให้บริการ SMS อีเมล หรือคลาวด์ใด ๆ

## 4. โดเมน / DNS / HTTPS
- ชื่อ **`ancapi.<โดเมนของโรงพยาบาล>`** — DNS สาธารณะ (A record) ชี้ไปที่ IP สาธารณะของโรงพยาบาล
- IP สาธารณะควรคงที่ (หรือใช้ Dynamic DNS)
- HTTPS: Caddy ขอใบรับรอง Let's Encrypt ให้อัตโนมัติ (ต้องเปิดพอร์ต 80 ตามข้อ 3)
  ถ้าโรงพยาบาลมี reverse proxy / WAF หรือใบรับรองของตัวเองอยู่แล้ว แจ้งได้ ปรับให้ใช้ของโรงพยาบาลได้
- แอปฝั่งผู้ใช้ยังอยู่ที่ https://phimai-hospital.github.io (QR ที่พิมพ์แล้วใช้ได้ต่อ) เซิร์ฟเวอร์ต้องยอมให้เว็บนี้เชื่อมต่อ (ตั้งค่าให้แล้ว)

## 5. สำรองข้อมูลและพื้นที่
- ตัวติดตั้งตั้งงานสำรองข้อมูล **ทุกคืน 02:15 น.** (pg_dumpall บีบอัด) เก็บ 14 วันล่าสุด
  พร้อมสำเนาคีย์เข้ารหัสและไฟล์ตั้งค่าที่จำเป็นต่อการกู้คืน
- ขอ **ที่เก็บแยกจาก VM**: ไดรฟ์ภายนอก หรือ share ในห้อง/อาคารอื่น (ประมาณ 50 GB) mount ที่ VM เช่น `/mnt/backup`
- แนะนำเพิ่ม: snapshot ระดับ VM ตามรอบปกติของไอที
- ข้อมูลที่ลบบัญชีแล้วเก็บแบบไม่ระบุตัวตน 5 ปี แล้วลบอัตโนมัติ (อนุมัติโดยผู้อำนวยการ)
- ซ้อมกู้คืนข้อมูล 1 ครั้งก่อนเปิดใช้จริง แล้วทุก 3 เดือน

## 6. ใครทำอะไร
**ฝ่ายไอทีโรงพยาบาลทำ**
1. สร้าง VM ตามข้อ 1–2 และ IP ภายในแบบคงที่
2. DNS + ไฟร์วอลล์ ตามข้อ 3–4
3. ที่เก็บสำรองข้อมูล ตามข้อ 5
4. ให้สิทธิ์ SSH แก่ผู้พัฒนา (เพิ่ม SSH public key) จากเครือข่ายภายใน/VPN
5. อนุมัติการติดตั้งซอฟต์แวร์ข้างต้น

**ผู้พัฒนาทำ (ผ่าน SSH หลังได้รับอนุมัติ)**
- รันตัวติดตั้งชุดเดียว `backend/deploy/install.sh`: Docker, Supabase, Caddy, ค่าความปลอดภัย, ตารางฐานข้อมูล,
  ผู้ดูแลระบบคนแรก, งานสำรองข้อมูล
- ตรวจจากภายนอกด้วย `backend/deploy/check-server.sh` แล้วส่งผลให้ไอที
- เชื่อมแอปกับเซิร์ฟเวอร์ **หลังไอทีและผู้บริหารอนุมัติเท่านั้น**
